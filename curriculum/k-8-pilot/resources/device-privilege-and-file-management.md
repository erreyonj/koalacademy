# Device Privilege and File Management

How iPads enter the room, how students earn and keep the privilege of using them, and what
happens for students who lose it. This is the operating plan behind `KSN.5` (File Management)
and the Koala lab days in the [concept rotation](../playbook/lesson-structure.md#concept-rotation-across-meetings-post-intro).

## The standing decision

Using an iPad in this room is a **privilege, not a default**. The privilege is earned by
demonstrating correct file usage and kept by continuing to use the device correctly. A
student who loses the privilege does not fall behind on the music — they move to a
**written-learning version** of the same lesson (see below) until the privilege is restored.

## Identity: Clever, Untitled, and a per-student folder

A shared cart is not assigned 1:1. Students still need **unique** working files that a
classmate cannot open or change. **Clever** is the identity layer.

Each student signs into their **own** school account through Clever. That account is what
holds their **Untitled** login and their **folder**. Permissions are the lock:

- The student can edit **only** their own folder
- The teacher can open every folder
- A classmate has **no** permission on it

Yesterday’s project lives in that account, so any iPad on the cart can be the one they pick
up. Signing in is how they get **their** work. Signing out is how the next class does not.

Do **not** use one shared class folder that every student can write. Anyone who can see that
folder can rename, move, or overwrite a classmate’s file. A filename does not stop that.

### Local files on the iPad

Clever does not hide a project left **inside Koala on the device**. The cloud folder is the
copy that counts. The lab exit also **clears the local project** so the next student cannot
open it.

## First Koala lab day is a file-management lesson

The **first lab meeting that puts Koala in front of students is `KSN.5`**, taught before any
open production. Nobody gets a device to "just make a beat" until the class has been taught,
I do / We do / You do, how to:

- Sign in through **Clever** to **their** account
- Open Koala and the project in **their** folder (not a classmate’s)
- Name and save / export into **their** folder (no ad-hoc names, no saving to random spots)
- Use the hamburger menu, screen-record, and IMPORT VIDEO / export path from `KSN.5`
- Sign **out**, clear the local project, and put the device away at collection

Curriculum source: `KSN.5` in [KOALACADEMY.md](../../KOALACADEMY.md).

**Band note.** This privilege gate applies wherever students touch iPads: all of 6-8, and the
**iPad-ready 5th-grade rotation** in the 3-5 hybrid ([3-5-band-differentiation.md](3-5-band-differentiation.md)).
That rotation uses the same Clever sign-in and per-student folder. 3rd and 4th grade (and any
not-ready 5th section) do not run student iPads on these lessons, so the privilege gate does
not apply to them — they use the projected + instrumentation path and its content/literacy
fallback instead.

## Sign-in and sign-out take class time

Signing in and signing out are mastered in class the same way save and export already are.
On a shared cart, a device left signed in **is** the previous student’s account.

| When | Minutes | What happens |
| --- | --- | --- |
| First lab (`KSN.5`) and the next few production meetings | Use the full device-handout window in [lesson-structure.md](../playbook/lesson-structure.md#6-8-production-days) (about 7 min in, and the last 5 min out) | I do / We do / You do on Clever, folder, save, sign-out, local clear. Shrink the You-do until the class can leave every iPad in a correct state |
| Later production days | Compress toward 3–4 min in and a short sign-out in Closing Crew | Same steps, faster. Restore the long You-do |

Device handout and collection stay I do / We do / You do. The musical work of the lab sits
between a correct sign-in and a correct sign-out.

## The exit ticket = the privilege gate

Correct file usage is the **exit ticket** on the first Koala day and stays the running bar on
every lab day after. To "pass" and keep the privilege, a student leaves the device in a
correct state:

- Project is **saved** in **their** folder with a correct name
- No other student’s files were opened, renamed, moved, or deleted (they should not have
  permission; opening someone else’s account is still a privilege break)
- **Clever / Untitled is signed out**
- Local Koala project is cleared (or the Shared iPad session has ended)
- Device is returned, charged path respected, headphones coiled

A student who cannot meet the bar on day one repeats the file-management steps rather than
advancing to open production. This is a routine, so it is rehearsed, not sprung.

## Losing and restoring the privilege

Treat device privilege like any other classroom routine inside CREW / CRISP
([routines-and-protocols.md](../playbook/routines-and-protocols.md)) — clear expectation,
visible steps, a way back.

1. **Warning / redirect** — misuse (off-task apps, mishandling files, ignoring collection,
   leaving an account signed in) is named and corrected in the moment.
2. **Privilege paused** — repeated or serious misuse pauses the student's iPad privilege for a
   set window. The student moves to the written-learning version for that lab, so no content
   is missed.
3. **Restoration** — the student re-earns the privilege by re-passing the file-management
   check (the same exit-ticket bar), plus any repair owed to the class (e.g. restoring a file
   they moved).

## Written-learning version (the fallback)

Every Koala lab day has a **written / unplugged version** that hits the **same concept target**
so a student off the device still does the day's musical work. Sources for that version:

- The **keyboard station** and body percussion for anything hands-on
  ([teaching-notes.md](../playbook/teaching-notes.md#student-instrument--keyboards))
- The **notebook** for notation, planning, listening, and reflection
- Corrective/reinforcement pages from [written-work.md](written-work.md) and
  [booklist.md](booklist.md) matched to the lab's concept

The written version is a **parallel track, not a punishment worksheet**: a student can rejoin
the device track the moment the privilege is restored and should not be conceptually behind
when they do. This also doubles as the built-in fallback for any day the iPads are unavailable.
